- (constraint by user) Legacy transport, legacy framing, and compatibility with old FujiNet Atari software are out of scope and must not influence the design.

- (decision) Freeze SIO device ID 0x7F as the fixed Atari NIO channel address; it selects only the SIO W/R byte-pipe envelope, never a FujiBus service, and an address collision reports NIO unavailable with no fallback, discovery, or legacy behavior.
- (decision) Supersede the initial SLIP direction: Atari NIO SIO carries packet-native FujiBus request and response packets; SIO transaction boundaries, not SLIP delimiters, define packet boundaries. Do not add SLIP escaping or a stream transport to the Atari path.
- (decision) Set the initial maximum packet-native SIO payload to 1024 bytes for both W requests and R responses, defined by one shared named compile-time contract constant so builds and performance experiments may change it together. AUX carries the exact SIO payload length; a FujiBus packet exceeding the configured limit fails with a defined NIO message-too-large transport error and is never implicitly segmented.
- (decision) Supersede the initial 1024-byte limit: set the initial maximum packet-native SIO payload to 512 bytes for both W requests and R responses, defined by one shared named compile-time contract constant so builds and performance experiments may change it together. W and R carry exact payload length in AUX and matching DCB byte count; a FujiBus packet exceeding the configured limit fails with a defined NIO message-too-large transport error and is never implicitly segmented.
- (decision) Add NIO-only P polling at SIO device 0x7F: a valid P always returns ACK, COMPLETE, and a fixed three-byte status payload of state (idle, pending, ready, or fault) plus little-endian queued response size. The client polls P, then sends R with that exact size only when ready. NAK remains reserved for malformed/rejected transport transactions, never means pending.
- (decision) Make PROC an opt-in NIO readiness notification. The library is polling-only by default and never installs, replaces, or silently owns an Atari IRQ/VPRCED handler. An application that owns/chains its handler may call an ISR-safe constant-time library notification hook that only latches a flag; outside IRQ context the library/application confirms readiness and size with P before R. The board emits a bounded, rate-limited PROC pulse only when its NIO response queue becomes ready; no source, request ID, or reason is encoded on the shared line, and a missed or false pulse is harmless because the queue remains until fetched/reset and polling remains correct.
- (constraint) Atari NIO v1 physically requires CMD and UART data input/output at standard 19,200 baud. Board-driven data output and PROC use released-idle open-drain behavior. INT, MTR, CKI, and CKO have no NIO protocol semantics and must remain electrically benign. Physical acceptance measures logic levels, no contention, command-to-control timing, data/checksum timing, abort/reset recovery, and both PROC opt-in and polling-only behavior; it makes no high-speed claim.
- (decision) Require Clock, Network, File, and Disk as the mandatory real-Atari Atari NIO service acceptance set. Clock proves a small deterministic exchange; Network proves open/write/read/close with a delayed readiness path; File proves persistent write/read; Disk proves read and write against an already-mounted supported image. Disk acceptance uses the established service/media workflow and does not reopen disk-media design.
- (direction) Atari FujiNet-NIO must act as the user's D: drive as well as the NIO application peripheral: a stock Atari boots from D1 over SIO, and the product must serve URI-backed ATR images as D1, D2, and subsequent units through the established disk-slot and boot-mode model.
- (decision) Define two deliberately separate Atari SIO ingress planes on the same official FujiNet hardware: (1) NIO application channel at device 0x7F with packet-native FujiBus W/P/R, and (2) standard Atari disk frontend at D1-D8 device IDs for OS boot and mounted ATR sector I/O. The disk frontend translates only standard Atari disk transactions into internal IORequest/IOResponse operations for the existing DiskDevice/DiskService, then encodes standard sector replies; it never exposes FujiBus framing to the Atari OS.
- (constraint) The required Atari disk frontend is not LegacyTransport and must not reuse or expand legacy FujiNet service adapters, device mappings, configuration commands, N:, R:, or proprietary framing. It is a purpose-built D: bootstrap/media adapter limited to standard Atari disk semantics and isolated from the 0x7F NIO channel except for shared physical SIO, disk slots, and DiskDevice service contract.
- (decision) Atari startup uses the existing boot configuration policy: config mode mounts the flashed Atari configuration/boot ATR URI as the D1 candidate; normal mode restores user-selected URI-backed D1-D8 slots. The disk frontend supplies the selected D1 image during OS boot. The configuration ATR contains the cc65 XEX acceptance/config applications, so no separate non-FujiNet loader is required.

- (decision) Supersede the DiskDevice IORequest translation decision: the standard Atari D1-D8 SIO frontend composes the existing DiskService directly, as the machine-native disk protocol boundary. DiskDevice remains the FujiBus IORequest/IOResponse wrapper used by 0x7F NIO and other NIO clients; both paths share DiskService slots, boot mounts, URI resolution, image parsing, geometry, and read/write behavior.
- (decision) Supersede the four-state P design: P has exactly three states, encoded as byte 0 , , ; bytes 1-2 are little-endian queued response length only for ready and zero otherwise. P has no fault state or request flags. Valid requests always yield a normal FujiBus response, including service/transport error status; malformed/rejected SIO transactions receive immediate NAK and queue nothing.
- (decision) Correction of prior entry: P has exactly three states in byte 0: 0 means idle, 1 means pending, and 2 means ready. Bytes 1-2 are little-endian queued response length only when ready and are zero otherwise. P carries no fault or request flags; request outcomes remain FujiBus responses and malformed SIO is immediate NAK.
- (decision) Add optional NIO capability query Q at SIO address 0x7F. Q has zero AUX/DCB length, is valid only when no NIO transaction is queued, and directly returns four bytes: wire revision 1, little-endian advertised maximum payload, and feature flags. Feature bit 0 denotes advisory PROC readiness support; remaining v1 bits are zero and ignored. Q creates and consumes no W/P/R transaction.
- (decision) No Atari application is required to issue Q. The public library's default remains the fixed 512-byte v1 payload baseline. An application that explicitly opts in to capability discovery may use the lesser of its compiled capacity and Q's advertised maximum; this query cannot affect D1-D8 boot because it is confined to the independent 0x7F plane.
- (decision) Clarify Q and v1 capacity: Q is legal only at idle with zero AUX/DCB length; a nonzero query length or Q while pending/ready is immediate NAK. Every wire-revision-1 device supports the full 512-byte baseline, so discovery remains optional. A lower-capacity profile requires a new wire revision and matching fixtures.
- (decision) Migration to this contract replaces SLIP framing, padded reads, and legacy 0x71 aliases in the Atari client, firmware, NetSIO, AltirraSDL, profiles, and v1 conformance tests. Historical legacy tests may remain but are explicitly excluded from v1 conformance and acceptance.
- (decision) Do not add an Atari-only cancel command in wire v1. Use the established one-outstanding-request semantics: W is valid only at idle and is NAK while pending/ready; a local client timeout does not cancel an accepted request, later traffic observes P, and terminal R clears the response. The library never auto-retries after timeout; applications retry only semantically safe operations. Device/SIO recovery handles a permanently stuck transaction.
- (decision) Clarify fixed control replies and R recovery: Q uses AUX 0 with DCB receive length 4; P uses AUX 0 with DCB receive length 3. A bad-length or malformed R is NAK and retains a ready response; a valid R consumes the response slot and makes P idle even if the client-side data transfer is interrupted. Acceptance names rejected W, malformed R, interrupted R, and reset recovery rather than an undefined abort path.
- (decision) Before disk adapter implementation, freeze its v1 fixture matrix in the first disk story: boot plus mounted ATR read, write, and status behavior. Formatting, PERCOM, high-speed, and non-ATR media remain excluded from that initial matrix until separately accepted.
- (decision) Correct SIO observability: Q and P fixed DCB receive sizes are client/fixture requirements (4 and 3 respectively), not device validation rules, because physical SIO delivers the command AUX and serial data but not the Atari DCB byte-count field. The device validates observable AUX/state and emits the fixed reply. The same distinction applies to W/R DCB matching; R rejection is based on observable AUX length and command validity.
- (capability) CAP-6: Provide a native Atari BASIC N: CIO device-handler capability, installed by the supported startup/config ATR path, so BASIC can OPEN N1:-style supported URIs and use NetworkService through the public NIO client without legacy transport.
- (constraint) The native BASIC N: handler maps its open/read/write/status/close lifecycle to modern NetworkService URI-and-handle operations exclusively over packet-native 0x7F. It must not use LegacyTransport, SIO 0x71-0x78, old FujiNet command encodings, or compatibility adapters.
- (decision) Treat N1:-style user syntax as a new native Atari CIO API rather than legacy FujiNet compatibility. The supported startup/config ATR installs the handler; NIO service Network handles remain the sole link state.

- (decision) The native Atari BASIC N: handler follows the existing BBC model: on CIO OPEN it calls the public fn_open API and stores the returned fn_handle_t against the Atari IOCB; GET, PUT, STATUS, and CLOSE call fn_read, fn_write, fn_info, and fn_close for that handle. N1: is user-facing device/path syntax, not a distinct network-slot protocol. Capacity is the existing library session limit and exhaustion fails OPEN normally.
- (decision) Native N: handler residency follows normal Atari CIO practice: startup installs a resident handler below adjusted MEMLO and registers HATABS. Installation is idempotent for the same handler and rejects a different existing N: handler without replacing it; it remains valid across BASIC/DOS program loads until reset.
- (decision) Native N: uses BBC-aligned semantics: CIO read open maps to fn_open GET, write open to PUT, update open to POST; GET/PUT use bounded 128-byte per-open IOCB caches over public fn_read/fn_write; STATUS calls fn_info and reports EOF/buffer/error through defined standard CIO completion; CLOSE flushes then fn_close. No dynamic allocation or automatic retry.

For CIO write/update POST/PUT, OPEN sets FN_OPEN_BODY_UNKNOWN; after flushing buffered bytes, the handler issues exactly one zero-length fn_write at the final offset before first STATUS, read, or CLOSE to commit the body. The handler adds no retry beyond fn_write library policy.
